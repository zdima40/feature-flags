# Angular: правила для AI

Применяются к `frontend/` вместе с корневым `AGENTS.md`.
Адаптировано из [Angular Best Practices](https://angular.dev/assets/context/best-practices.md) ([CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)). Проверено 17.11.2026.

- Проверять установленную версию Angular перед выбором API; не переносить возможности новой версии в старую без проверки совместимости.
- Использовать строгую типизацию, вывод очевидных типов и `unknown` вместо `any`.
- Использовать standalone-компоненты; начиная с Angular 20 не указывать `standalone: true`. В Angular 22+ не задавать явно OnPush: это поведение по умолчанию.
- Для локального состояния использовать `signal()`, для производного — `computed()`, для синхронизируемого — `linkedSignal()`. Изменять signals через `set()` или `update()`.
- Использовать `input()`, `output()`, `model()`; привязки хоста описывать через `host`.
- Загружать функциональные маршруты лениво. Импортировать только необходимые директивы и pipes.
- В шаблонах применять `@if`, `@for`, `@switch`, привязки `class`/`style` и `AsyncPipe`; сложную логику выносить в TypeScript.
- Для новых форм в Angular 22+ предпочитать Signal Forms; иначе Reactive Forms.
- Использовать `inject()`; в Angular 22+ предпочитать `@Service` для новых singleton-сервисов.
- Использовать `NgOptimizedImage` для статических изображений, кроме inline base64.
- Обеспечивать WCAG AA и прохождение axe-проверок: клавиатура, фокус, контраст и корректная семантика.
